Redes de Computadores

Cómo se comunican los computadores: del bit que viaja por un cable hasta el HTTP que pinta una página web. Esta guía recorre las siete capas en orden, con diagramas, fórmulas y ejemplos resueltos.

01

Introducción y arquitectura de red

El vocabulario y los modelos. Sin esta base, todo lo demás se confunde.

Una red de computadores es un sistema que permite intercambiar información entre equipos. Para entender cómo funciona necesitamos dos cosas: un vocabulario común (host, router, enlace, protocolo…) y un modelo en capas que descomponga el problema en piezas manejables.

Terminología básica

Nodo
Cualquier equipo conectado capaz de enviar y recibir información.
Host / estación
Nodo que hospeda aplicaciones (cliente, servidor o peer).
Router
Dispositivo de capa 3 que interconecta redes distintas reexpidiendo paquetes IP.
Switch
Dispositivo de capa 2 que reexpide tramas dentro de una LAN.
Hub
Dispositivo de capa 1: amplifica la señal pero no entiende tramas.
Enlace
Conexión física entre dos nodos. Punto-a-punto si es directa, extremo-a-extremo si es lógica entre estaciones (puede atravesar routers).
Protocolo
Conjunto de reglas que deben seguir las entidades de una capa para entenderse.
Pila de protocolos
Conjunto concreto de protocolos usados en una comunicación. Ej: HTTP / TCP / IP / Ethernet.

Topologías y tipos de redes

Las redes se clasifican por extensión geográfica y por topología física.

Las tres topologías clásicas. En realidad, casi todas las LAN modernas son estrellas conmutadas.

Tipos de envío

  • Unicast: uno a uno. La inmensa mayoría del tráfico.
  • Multicast: uno a un grupo concreto suscrito. Ideal para streaming.
  • Broadcast: uno a todos los nodos de la red. Necesario en ARP, DHCP.
  • Anycast: uno al "más cercano" de un grupo (mismo destino, varias instancias).

El modelo OSI (7 capas)

El modelo OSI (Open Systems Interconnection, ISO) divide la comunicación en 7 capas. Es un modelo de referencia: en la práctica nadie implementa OSI puro, pero el vocabulario se sigue usando.

OSI a la izquierda, TCP/IP a la derecha. Sesión y presentación apenas se usan en la práctica: HTTPS las cumple por su cuenta (TLS).

Regla mnemotécnica

De arriba abajo (L7 → L1): Aplicación, Presentación, Sesión, Transporte, Red, Enlace, Física. "Almeja Para Sopa Tiene Rica Espina Fresca".

El modelo TCP/IP

TCP/IP es el modelo real de Internet. Tiene 4 capas en lugar de 7, y fue diseñado de abajo hacia arriba (a partir de lo que funcionaba). Las equivalencias se ven en el diagrama anterior.

Idea clave

OSI es un modelo conceptual útil para hablar. TCP/IP es el modelo operativo: si despliegas algo en Internet, estás usando TCP/IP.

Encapsulado de protocolos

Cuando un mensaje baja por la pila, cada capa añade su propia cabecera (y a veces cola) a los datos de la capa superior. En el extremo receptor el proceso es inverso: cada capa quita su cabecera y pasa lo de dentro a la superior.

Cada capa añade su cabecera. En el destino, cada capa la quita en sentido inverso ("desencapsulado").
Nombres de la PDU por capa

mensaje (aplicación) → segmento/datagrama (transporte) → paquete (red) → trama (enlace) → bits (física).

02

Capa física

De bits abstractos a voltios, fotones u ondas. Y, sobre todo, cuánto se puede meter por un canal.

La capa física se encarga de convertir bits en señales que viajen por un medio (cable, fibra, aire) y de recuperarlos al otro lado. Aquí se estudia qué señales pueden transmitirse, cómo de rápido y con qué calidad.

Señales periódicas y Fourier

Una señal sinusoidal pura se describe con:

s(t) = A · sin(2π f t + φ) // A: amplitud · f: frecuencia (Hz) · φ: fase T = 1 / f // periodo (s)

Cualquier señal periódica se puede descomponer en una suma de sinusoides (serie de Fourier). El conjunto de frecuencias que ocupa una señal es su ancho de banda B, medido en Hz. Cuanto más ancho de banda, más información se puede transmitir.

Decibelios, SNR y atenuación

Las potencias en telecomunicaciones se manejan casi siempre en decibelios, porque cubren rangos enormes y porque las atenuaciones se suman en escala logarítmica.

dB = 10 · log10(M₁ / M₂) dBm = 10 · log10(P / 1mW) SNR(dB) = 10 · log10(S / N)

El balance de potencias en un enlace se plantea así:

Pt − L = Pr // potencia recibida = transmitida − atenuación Pr − Sr = M ≥ 0 // margen de enlace ≥ 0 → enlace viable
Pt
Potencia transmitida.
L
Atenuación (loss) acumulada del medio.
Pr
Potencia recibida.
Sr
Sensibilidad mínima del receptor.
M
Margen: cuánto sobra. Si es negativo, el receptor no detecta nada.

Símbolos, baudios y bits

Por el canal viajan símbolos (formas de onda distinguibles), no bits directamente. Cada símbolo lleva varios bits según cuántos símbolos distintos tenga el alfabeto.

k = log2(M) // bits por símbolo Rs = 1 / Ts // símbolos/s = baudios (Bd) Rb = Rs · log2(M) // bits/s
Error típico

Confundir baudios (símbolos/s) con bits/s. Solo coinciden si M = 2 (binario, 1 bit/símbolo). Con QAM-16 son cuatro veces más bits que baudios.

Codificaciones de línea

Una codificación de línea define cómo se representa cada bit con voltajes (o intensidad de luz) a lo largo del tiempo. Cada esquema busca un equilibrio entre simplicidad, sincronismo y eficiencia espectral.

Tres codificaciones para la misma secuencia 10110010.
  • NRZ-L: nivel alto = 1, nivel bajo = 0. Sencillo pero sin transiciones si hay muchos 0 o 1 seguidos.
  • NRZ-M: cambia de nivel cada vez que aparece un 1 (mantiene si aparece un 0). Diferencial.
  • NRZ-AMI: alterna polaridad en cada 1, los 0 son nivel cero.
  • Manchester: transición en el centro de cada bit. Sincronismo perfecto, pero el doble de ancho de banda.
  • 4B5B: agrupa 4 bits en 5 antes de codificar (Fast Ethernet). Evita largas secuencias sin transición.

Nyquist y Shannon

Dos teoremas marcan el techo de lo que se puede transmitir por un canal.

Nyquist (canal sin ruido)

Rs ≤ 2 · B Rb ≤ 2 · B · log2(M)

Limita los símbolos por segundo en función del ancho de banda. Suponiendo no hay ruido, podríamos meter cualquier número de bits aumentando M.

Shannon-Hartley (con ruido)

C = B · log2(1 + S/N) Rb ≤ C

Limita los bits/s reales en función del ancho de banda y la relación señal/ruido. Ya no se puede subir M indefinidamente porque el ruido te confunde símbolos.

Ejercicio resuelto · Shannon

Canal con B = 1 MHz y S/N = 15. ¿Capacidad máxima?

C = B · log₂(1 + S/N)
C = 10⁶ · log₂(1 + 15)
C = 10⁶ · log₂(16)
C = 10⁶ · 4 = 4 Mb/s
Ejercicio resuelto · símbolos a bits

Señal con M = 16 símbolos y Ts = 2 µs. Calcula Rs, k y Rb.

k  = log₂(16) = 4 bits/símbolo
Rs = 1 / 2µs  = 500 000 Bd
Rb = Rs · k   = 500 000 · 4 = 2 Mb/s

Modos de transmisión

  • Simplex: un solo sentido (TV, radio).
  • Half-duplex: dos sentidos pero no simultáneos (walkie-talkie).
  • Full-duplex: dos sentidos a la vez (Ethernet conmutada, teléfono).
  • Serie vs paralelo: serie envía bit a bit por un solo canal; paralelo envía varios bits a la vez. Serie gana en distancias largas.
  • Asíncrona vs síncrona: asíncrona usa bits de start/stop por carácter; síncrona transmite tramas con sincronismo de reloj continuo.

03

Capa de enlace de datos

Organiza los bits en tramas, decide quién transmite y detecta los errores. Ethernet vive aquí.

Tramas y métricas de enlace

La capa de enlace agrupa bits en tramas. Cada trama lleva direcciones MAC (de origen y destino), datos, y un mecanismo de detección de errores (CRC en Ethernet).

Tt = L / Vt // tiempo de transmisión (s) Tp = D / Vp // tiempo de propagación (s) RTT ≈ 2 · Tp // round-trip time aproximado
L
Longitud de la trama en bits (¡cuidado, no bytes!).
Vt
Velocidad de transmisión del enlace en b/s.
D
Distancia entre extremos en metros.
Vp
Velocidad de propagación en el medio.
Ejercicio resuelto · tiempos

Trama de L = 1500 B, enlace de 100 Mb/s, distancia 100 m, Vp = 2·10⁸ m/s.

L  = 1500 · 8 = 12 000 bits
Tt = 12 000 / 10⁸ = 120 µs
Tp = 100 / (2·10⁸) = 0,5 µs

En LAN domina Tt. En enlace de larga distancia (satélite) dominaría Tp.

Conmutación de circuitos vs paquetes

Conmutación de circuitos

Se reserva un canal de extremo a extremo antes de transmitir (teléfono clásico). Garantiza ancho de banda pero desperdicia recursos cuando no hay tráfico.

Conmutación de paquetes

Cada paquete viaja por separado y comparte enlaces con otros. Mucho más eficiente, pero introduce retardo variable y posibles pérdidas en colas. Es lo que usa Internet.

Control de acceso al medio (MAC)

Cuando varios nodos comparten un canal hay que decidir quién transmite en cada momento.

CSMA/CD (Carrier Sense Multiple Access / Collision Detection)

  1. Escuchar el canal hasta que esté libre.
  2. Transmitir mientras se sigue escuchando.
  3. Si se detecta colisión: enviar jam, esperar backoff exponencial y volver a 1.

Para que el emisor pueda detectar una colisión, debe seguir transmitiendo el tiempo que tarda la colisión en volver desde el otro extremo. De ahí la trama mínima:

Tt ≥ 2 · Tp Lmin = 2 · Tp · Vt

CSMA/CA (Collision Avoidance, Wi-Fi)

  1. Escuchar el canal hasta que esté libre durante un tiempo mínimo.
  2. Transmitir.
  3. Esperar ACK del receptor.
  4. Si no llega ACK: backoff aleatorio y reintentar.
Error típico

Pensar que Wi-Fi usa CSMA/CD. No puede: en radio el emisor no oye mientras transmite (el problema del "terminal oculto"). Por eso Wi-Fi usa CA con ACK explícito.

Ethernet

La trama Ethernet II es uno de los formatos más usados del mundo. Se ha mantenido casi sin cambios desde los años 80.

Estructura de la trama Ethernet II.

Direcciones MAC

Son 48 bits, 6 octetos en hex, separados por :. Ejemplo: 00:1A:2B:3C:4D:5E. Los 3 primeros octetos identifican al fabricante (OUI). La dirección FF:FF:FF:FF:FF:FF es broadcast Ethernet.

Switch aprendiz

Cuando le llega una trama por un puerto, aprende que la MAC origen está en ese puerto. Si la MAC destino la conoce, reenvía solo por su puerto; si no, hace flooding.

VLANs y Spanning Tree

  • VLAN: redes virtuales sobre la misma infraestructura física (etiqueta 802.1Q). Separa tráficos sin tener que añadir hardware.
  • STP / RSTP: evita bucles en topologías con redundancia, podando enlaces hasta dejar un árbol.
  • TSN: extensiones para tráfico en tiempo real con latencia garantizada.

Detección y corrección de errores

Por el canal aparecen errores. La capa de enlace los detecta (y a veces los corrige) mediante bits de redundancia.

Paridad

Añade 1 bit a cada bloque de m bits de modo que el número total de 1s sea par (o impar). Detecta cualquier número impar de errores. No detecta errores pares.

Checksum

Suma bloques de m bits y envía el resultado. TCP/IP usa suma de enteros de 16 bits en complemento a 1.

CRC (Cyclic Redundancy Check)

Es el método estrella en enlace. Trata el mensaje como un polinomio y divide entre un polinomio generador G usando aritmética módulo 2 (XOR).

CRC = (M · 2^n) mod G M' = M · 2^n + CRC // Receptor: acepta si M' mod G = 0
Error típico

Hacer la resta como en aritmética normal. En CRC, suma y resta son XOR. No hay acarreo.

Distancia de Hamming

Si la distancia mínima entre palabras válidas del código es d:

// errores que se pueden corregir bits_corregibles = ⌊(d − 1) / 2⌋

ARQ y ventana deslizante

Los protocolos ARQ (Automatic Repeat reQuest) consiguen una transmisión fiable usando ACKs y retransmisiones.

Stop & Wait

Solo hay una trama "en vuelo". Se envía una, se espera ACK, y solo entonces se envía la siguiente. Sencillo pero ineficiente con RTT grande.

U = 100 · Tenvío / RTT // utilización en %

Ventana deslizante

Permite w tramas sin confirmar a la vez. La ventana avanza a medida que llegan ACKs.

Las dos variantes principales de ventana deslizante.
// utilización con ventana U = 100 % si w · Tenvío ≥ RTT U = 100 · w · Tenvío / RTT si w · Tenvío < RTT // nº de secuencia necesarios NS ≥ w + wr bits_seq = ⌈log2(NS)⌉
Ejercicio resuelto · ventana

Tenvío = 1 ms, RTT = 20 ms, w = 10. ¿Utilización?

w · Tenvío = 10 · 1 = 10 ms < RTT = 20 ms
→ U = 100 · 10 / 20 = 50 %

Para llegar al 100 % necesitaría w ≥ RTT / Tenvío = 20.
Ejercicio resuelto · números de secuencia

Ventana emisión w = 5, ventana recepción wr = 4. ¿Cuántos bits para los números de secuencia?

NS ≥ w + wr = 5 + 4 = 9
bits_seq = ⌈log₂(9)⌉ = 4 bits   (16 valores: sobra)
Ejercicio resuelto · CRC paso a paso

Mensaje M = 1101011011, generador G = 10011 (grado n = 4). Calcular el CRC.

1) Añadir n=4 ceros a M:   11010110110000
2) Dividir entre G usando XOR:

   11010110110000  ÷  10011
   10011
   -----
   10011 1
   10011
   -----
   00000 0110000   → bajamos bits y seguimos…
                  → finalmente queda resto = 1110

CRC = 1110
Trama enviada: M + CRC = 11010110110000 + 1110 = 11010110111110

El receptor divide 11010110111110 ÷ 10011. Si resto = 0, trama OK.
04

Capa de red

Conectar redes distintas. IP, routers, direcciones jerárquicas y rutas que cruzan continentes.

Por qué hace falta la capa 3

La capa 2 sirve perfectamente para una LAN: hay pocas decenas o cientos de nodos, todos se conocen por su MAC, los switches aprenden por sí solos. Pero no escala:

  • Las MAC no son jerárquicas: no se pueden agregar rutas.
  • Broadcasts ARP saturarían la red mundial.
  • No hay forma de ir de una LAN Ethernet a una red Wi-Fi o a un enlace de fibra.

La capa de red interconecta redes mediante un sistema de direccionamiento lógico y jerárquico (IP), y unos dispositivos que toman decisiones de reexpedición (routers).

Filosofía de IP

IP es best effort: hace lo que puede, no garantiza nada. Los paquetes pueden perderse, duplicarse, llegar desordenados o corromperse. La fiabilidad se delega a TCP (capa de transporte).

IPv4 y cabecera

Una dirección IPv4 son 32 bits, escritos como cuatro octetos decimales separados por puntos: 155.210.153.238.

Cabecera IPv4 (mínimo 20 bytes). En naranja, los campos clave: TTL, fragmentación e IPs.
Version
4 para IPv4, 6 para IPv6.
IHL
Longitud de la cabecera en palabras de 32 bits. Suele ser 5 (=20 B).
Total Length
Tamaño total del paquete (cabecera + datos), máximo 65535 B.
Identification
Identifica todos los fragmentos del mismo paquete.
Flags / Offset
Control de fragmentación. Offset va en unidades de 8 bytes.
TTL
Cada router lo decrementa en 1. Cuando llega a 0, se descarta y se envía ICMP TTL exceeded.
Protocol
Qué protocolo va dentro: 6=TCP, 17=UDP, 1=ICMP.
Checksum
Comprueba solo la cabecera, no los datos.

Direcciones y CIDR

Una IP se divide en dos partes con la máscara de red: los bits altos identifican la red/subred, los bajos identifican al host dentro de ella.

Dirección IP AND Máscara = Dirección de red Hosts útiles = 2^(bits_host) − 2 // se restan la dirección de red y la de broadcast

La notación CIDR escribe la máscara como el número de bits a 1: 155.210.152.0/21 significa que los 21 bits altos son red.

ARP y DHCP

ARP (Address Resolution Protocol)

Para enviar una trama Ethernet necesito la MAC destino. Si solo conozco la IP destino (y está en mi LAN), uso ARP para preguntar.

ARP convierte una IP en su MAC dentro de la misma LAN.
Cuidado

Si la IP destino no está en mi red, no hago ARP de ella. Hago ARP del gateway por defecto y le envío la trama a él. La IP destino del paquete se mantiene; la MAC destino cambia en cada salto.

DHCP (Dynamic Host Configuration Protocol)

Cuando un host se conecta, normalmente no tiene IP. DHCP se la asigna:

  1. DISCOVER: cliente envía broadcast desde 0.0.0.0 a 255.255.255.255, UDP 67.
  2. OFFER: el servidor ofrece una IP.
  3. REQUEST: cliente pide formalmente esa IP.
  4. ACK: servidor confirma. Le entrega IP, máscara, gateway y servidor DNS.

NAT (Network Address Translation)

IPv4 tiene 2³² ≈ 4 300 millones de direcciones, agotadas hace años. La solución temporal es NAT: en una red doméstica todos usan IPs privadas, y el router las traduce a su única IP pública al salir.

El router NAT sustituye IP+puerto de origen al salir y deshace el cambio al volver.

Es eficaz pero rompe el modelo extremo-a-extremo: desde fuera no se puede iniciar una conexión a un host interno sin port forwarding. Por eso muchos protocolos (SIP, FTP activo) se llevan mal con NAT.

ICMP, ping y traceroute

ICMP (Internet Control Message Protocol) es el "canal de control" de IP. Sus mensajes más conocidos:

MensajeCuándoHerramienta
Echo Request / Replycomprobar si un host respondeping
TTL exceededTTL llega a 0 en un routertraceroute
Destination unreachablered/host/puerto inalcanzablevisible en muchos errores
Redirecthay mejor ruta para ese destino—

Traceroute es ingenioso: envía paquetes con TTL=1, luego TTL=2, etc. Cada router intermedio responde con TTL exceeded y así se descubre la ruta salto a salto.

Fragmentación IPv4

Si un paquete IP es más grande que la MTU del siguiente enlace, el router lo fragmenta. El destino final reensambla.

  • Todos los fragmentos comparten el campo Identification.
  • Flag More Fragments = 1 en todos salvo el último.
  • Offset en unidades de 8 bytes.
  • Cada fragmento salvo el último debe tener un payload múltiplo de 8 B.
Ejercicio resuelto · fragmentación

Paquete con 1400 B de datos (cabecera 20 B aparte). Sale a un enlace con MTU = 512 B.

Espacio para datos por fragmento: 512 − 20 = 492 B
Debe ser múltiplo de 8 → 488 B por fragmento (salvo el último).

Fragmento 1: 488 B   offset = 0     MF=1
Fragmento 2: 488 B   offset = 61    MF=1   (488/8 = 61)
Fragmento 3: 424 B   offset = 122   MF=0   (último)

Comprobación: 488 + 488 + 424 = 1400 B ✓

IPv6

IPv6 surge para superar el agotamiento de IPv4 y simplificar la cabecera. Direcciones de 128 bits (≈ 3,4·10³⁸).

Cambios clave
  • Cabecera fija de 40 B (sin opciones).
  • No hay checksum ni fragmentación en la cabecera base.
  • No hay broadcast: se usa multicast.
  • ARP sustituido por Neighbor Discovery (ICMPv6).
  • Autoconfiguración (SLAAC) sin DHCP.
Prefijos importantes

Estructura de Internet: AS y BGP

Internet se organiza en Sistemas Autónomos (AS), grandes redes gestionadas por una organización (un ISP, una universidad, una empresa). Dentro de un AS se usan protocolos interiores (OSPF, RIP); entre AS, BGP (Border Gateway Protocol), que toma decisiones por políticas, no solo por distancia.

05

Capa de transporte

De host a host ya tenemos IP. Aquí pasamos de aplicación a aplicación: puertos, fiabilidad y control de flujo.

Puertos y servicios

IP entrega paquetes a una máquina, pero una máquina ejecuta muchos procesos. Los puertos (16 bits, 0–65535) identifican el proceso destino dentro del host.

RangoTipoEjemplos
0–1023Sistema (well-known)22 SSH, 25 SMTP, 53 DNS, 80 HTTP, 443 HTTPS
1024–49151Registrados / usuario3306 MySQL, 5432 PostgreSQL
49152–65535Dinámicos / efímeroslos que abre tu navegador

Una conexión se identifica por la cuádrupla (IP_orig, puerto_orig, IP_dest, puerto_dest). Por eso puedes tener cientos de pestañas de Chrome conectadas al mismo servidor: cada una usa un puerto efímero distinto.

UDP — el simple

UDP es sin conexión, no fiable, sin control de flujo. Solo añade puertos y checksum opcional. Cabecera mínima de 8 bytes.

Cabecera UDP. Tan minimalista que apenas hay más que decir.
  • Sin conexión: no hay handshake.
  • Unidad: el datagrama. Preserva los límites del mensaje.
  • Checksum opcional en IPv4, obligatorio en IPv6.
  • Cuándo usarlo: DNS, juegos, streaming, multicast, QUIC (HTTP/3).

TCP — el fiable

TCP es orientado a conexión, fiable, ordenado, con control de flujo y de congestión. Es el caballo de batalla del Web, SSH, SMTP, etc.

Cabecera TCP. En naranja, los campos más relevantes para el control.

3-way handshake y cierre

Para abrir una conexión TCP se intercambian tres mensajes:

3-way handshake. Cada extremo elige un número de secuencia inicial (x, y) y los confirma el otro.

El cierre ordenado es un 4-way:

 Cliente → Servidor : FIN
 Servidor → Cliente : ACK             (puede seguir mandando)
 Servidor → Cliente : FIN             (cuando termina)
 Cliente → Servidor : ACK

Si algo va muy mal, cualquier extremo puede enviar RST y cerrar de golpe.

Control de flujo (ventana anunciada)

El receptor anuncia cuánto buffer libre tiene en cada ACK. El emisor no puede tener más bytes sin confirmar que ese tamaño.

VentanaAnunciada = BufferSize − Ocupado VentanaEmisión = min(vanun, vcong)
Ejercicio resuelto · ventana anunciada

Buffer receptor de 64 KiB, ocupado 20 KiB.

VentanaAnunciada = 64 − 20 = 44 KiB
El emisor no tendrá más de 44 KiB sin confirmar (sin contar congestión).
Error típico

Confundir control de flujo (proteger al receptor) con control de congestión (proteger a la red). Son dos problemas distintos y TCP gestiona los dos por separado.

Eficiencia: ACK retardado y Nagle

  • ACK retardado: en lugar de mandar ACK por cada segmento, el receptor espera un poco a ver si tiene datos que enviar (para piggyback) o si llega otro segmento (un ACK acumula varios).
  • Algoritmo de Nagle: el emisor agrupa pequeñas escrituras seguidas en un solo segmento, hasta que llega un ACK o el buffer está lleno.

Timeout adaptativo (Jacobson/Karels)

TCP no usa un timeout fijo; lo ajusta a la realidad de cada conexión midiendo el RTT real.

// Versión sencilla: DifRTT = MuestraRTT − EstimRTT EstimRTT += δ · DifRTT Timeout = 2 · EstimRTT // Versión Jacobson/Karels (la real): DesvRTT = |DifRTT| − EstimDesvRTT EstimDesvRTT += δ · DesvRTT Timeout = μ · EstimRTT + φ · EstimDesvRTT

Regla importante: no se toma muestra de RTT en segmentos retransmitidos (no se sabe a cuál corresponde el ACK).

06

QoS y control de congestión

La red tiene recursos finitos. Si todos compiten igual, todos pierden. QoS y congestión son los dos lados del mismo problema.

Mecanismos de QoS

QoS (Quality of Service) es el conjunto de técnicas para tratar mejor a unos tráficos que a otros según su importancia o tipo. No crea ancho de banda nuevo: solo lo reparte de otra forma.

MecanismoIdeaCuándo
FIFOUna cola, primero el que llega primerosimple, sin garantías
FQ (Fair Queueing)Una cola por flujo, se atienden en round-robinreparto equitativo
WFQ (Weighted FQ)Como FQ pero con pesospriorizar VoIP sobre descargas
DiffServClasifica por tipo de tráfico (campo DSCP)escalable, sin estado por flujo
IntServ + RSVPClasifica por flujo y reserva recursosgarantías estrictas, no escala

DiffServ vs IntServ

DiffServ

El emisor (o el primer router) marca los paquetes con un código DSCP. Los routers tratan cada paquete según su clase, sin saber a qué flujo pertenece. Escala bien, no requiere mantener estado.

IntServ

Antes de enviar, la aplicación reserva recursos extremo a extremo con RSVP (mensajes PATH y RESV). Cada router mantiene estado por flujo. Escala mal, pero da garantías reales.

Control de congestión TCP

La congestión ocurre cuando la red recibe más tráfico del que puede reexpedir. Las colas se llenan y empiezan a tirarse paquetes. TCP detecta la congestión por las pérdidas: si un segmento no se confirma, asume que la red está saturada.

La idea general:

Si no hay pérdidas → aumentar poco vcong Si hay pérdidas → reducir mucho vcong

TCP mantiene una ventana de congestión vcong independiente de la anunciada. La ventana real que usa es min(vanun, vcong).

Slow Start y Congestion Avoidance

Evolución típica de la ventana de congestión TCP (Tahoe).
  • Slow Start: empieza con vcong = 1 MSS. Cada ACK recibido duplica aproximadamente la ventana cada RTT. Crece exponencialmente.
  • Congestion Avoidance: al llegar a ssthresh, pasa a crecer linealmente (+1 MSS por RTT).
  • Timeout: si se pierde un segmento, se ajusta ssthresh = vcong / 2 y se vuelve a vcong = 1 MSS.

Variantes: Tahoe, Reno, SACK, Vegas

VarianteAporte clave
TahoeAñade retransmisión rápida: tras 3 ACK duplicados, retransmite sin esperar al timeout.
RenoAñade recuperación rápida: tras 3 ACK duplicados, no vuelve a slow start; baja a la mitad y sigue en congestion avoidance.
SACKACK selectivo: el receptor indica qué bloques tiene; el emisor retransmite solo los huecos.
VegasDetecta congestión por el aumento del RTT, antes de que haya pérdidas (proactivo, no reactivo).

ECN y RED — más allá de la pérdida

  • ECN (Explicit Congestion Notification): los routers, cuando empiezan a saturarse, marcan los paquetes en lugar de tirarlos. Los extremos reaccionan reduciendo la ventana sin haber perdido nada.
  • RED (Random Early Detection): el router descarta aleatoriamente paquetes antes de llenar su buffer. Como TCP reduce su ventana al perder, esto evita la sincronización de muchos flujos cayendo a la vez.
Error típico

Asumir que toda pérdida es por congestión. En enlaces inalámbricos a menudo se pierde por errores físicos. Eso confunde a TCP, que reduce la ventana innecesariamente.

07

Capas superiores

Sesión, presentación y aplicación. HTTP, DNS, SMTP y todo lo que realmente usas a diario.

Sesión y presentación

  • Sesión: establece, mantiene y cierra conversaciones entre aplicaciones. En TCP/IP no existe como capa separada; suele estar embebida en la aplicación.
  • Presentación: traduce el formato de los datos. Codificación de caracteres (UTF-8), serialización (JSON, XML), compresión, cifrado.

TLS es el ejemplo más claro de capa de presentación moderna: se sitúa entre TCP y la aplicación, cifra los datos y autentica el extremo. HTTPS = HTTP + TLS.

DNS

DNS traduce nombres de dominio (www.unizar.es) en direcciones IP (y mucho más). Es un sistema jerárquico y distribuido.

Jerarquía DNS, leída de derecha a izquierda en el nombre.

Resolución típica (iterativa)

  1. El cliente pregunta al resolver de su DNS local (ej: el del ISP).
  2. El resolver pregunta a un servidor raíz: "¿quién sabe de .es?"
  3. Raíz responde: "pregunta al servidor de .es".
  4. El resolver pregunta al servidor de .es: "¿quién sabe de unizar.es?"
  5. El de .es responde con el servidor autoritativo de unizar.
  6. El resolver pregunta a ese servidor y obtiene la IP.
  7. Devuelve la IP al cliente y la cachea.

SMTP y correo

SMTP envía correo entre servidores. Es un protocolo de texto, originalmente solo ASCII. Para adjuntar imágenes o caracteres no ASCII, se codifican con MIME (típicamente en base64).

  • SMTP (puerto 25 / 587): envío.
  • POP3 (110) / IMAP (143): lectura desde el cliente.
Error típico

Decir que SMTP "lee" correo. SMTP solo lo entrega entre servidores. Para leer usas IMAP o POP.

Redes superpuestas, P2P, UPnP

  • Red superpuesta (overlay): red lógica construida encima de otra red. Sus enlaces son túneles.
  • Tor: overlay para anonimato. Los datos pasan por varios nodos cifrados en capas (onion routing).
  • CDN: red de servidores distribuidos geográficamente que cachean contenido cerca del usuario.
  • P2P: los nodos actúan como cliente y servidor. BitTorrent es el ejemplo clásico.
  • UPnP: descubrimiento automático de dispositivos en una LAN (impresoras, NAS, abrir puertos en el router…).

Errores típicos en examen

Unidades

Usar bytes donde la fórmula pide bits (Tt = L/Vt). Confundir k y M. Olvidar que 1 kbps = 10³ b/s, no 2¹⁰.

Baudios ≠ bps

Solo coinciden cuando M = 2. Si te dan QAM-16, hay 4 bits por símbolo.

CSMA

Wi-Fi usa CSMA/CA, no CD. En radio no se detectan colisiones desde el emisor.

CRC

Hacer la resta en aritmética normal. ¡Es XOR! Sin acarreo.

Subredes

Olvidar restar la red y la broadcast en el número de hosts útiles.

Fragmentación

El campo Offset va en unidades de 8 bytes, no en bytes. Y todos los fragmentos salvo el último deben tener un payload múltiplo de 8.

ARP fuera de la LAN

Si la IP destino no está en mi red, hago ARP del gateway, no de la IP final.

TCP flujo vs congestión

La ventana anunciada protege al receptor; vcong protege a la red. La efectiva es el mínimo.

IP es best effort

IP no garantiza entrega. La fiabilidad la pone TCP por encima.

IPv6 no tiene broadcast

Lo reemplaza por multicast. Y ARP se sustituye por Neighbor Discovery (ICMPv6).
